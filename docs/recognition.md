# Распознавание рисунков

Изменения от 6 ноября 2026 года. Оформление холста сохранено.

## Что было причиной ошибок

- Старое сравнение выделяло по 40 точек на каждый штрих. При разном числе штрихов получались облака разной длины; поиск «свободного соседа» исчерпывал точки и возвращал бесконечное расстояние. Запасной способ сравнения поэтому не решал проблему разрывов линий.
- Направление движения пера штрафовалось, хотя видимая форма могла быть той же.
- Короткий штрих имел такой же вес, как длинный; центровка также зависела от числа штрихов. Для вытянутых фигур дополнительно резко менялся способ масштабирования.
- Первый распознанный фрагмент запечатывался, а следующие части пытались стать отдельными символами. Полнота оценивалась по числу отрывов пера автора образца.
- Диагностика `diag-live-templates.mjs` содержала собственную копию алгоритма, расходившуюся с рабочей версией.

## Как работает новая версия

Весь символ преобразуется в 96 точек, распределённых по длине видимых линий. Пробелы между штрихами не дорисовываются. Сравнение симметричное: оценивается и лишняя линия пользователя, и недостающая линия эталона. Учитываются среднее расстояние, его дальняя часть и покрытие формы.

Порядок штрихов и направление пера не задают смысл символа. Геометрическая ориентация сохраняется: перевёрнутые знаки различаются. Проверяются наклоны до 15° и небольшое изменение пропорций до 20%. Подготовленные варианты эталонов кешируются.

На холсте близкие штрихи могут дополнить уже прочитанный символ. Полнота зависит от покрытия формы, а не числа штрихов. При близких оценках остаётся существующий выбор вариантов. Результаты обрабатываются последовательно; очистка и отмена делают старые задания недействительными. Замыкающие контуры не участвуют в дальнейшем распознавании знаков.

Пороги сходства: 0.68 для сигилов, 0.66 для знаков; покрытие — от 0.86. Разница менее 0.08 между подходящими кандидатами требует выбора. Проценты в интерфейсе — сходство, а не вероятность правильного ответа.

## Проверки

```sh
npm test
npm run check
npm run build
npm run benchmark -- split
npm run benchmark -- reverse
npm run benchmark -- freehand
```

Бенчмарк вызывает рабочий `recognizeSymbol`. Первый образец каждого из 24 записанных символов исключён из базы сравнения. Классификация проходит среди символов той же зоны, как на сайте.

| Проверка отложенного образца | До изменения: первый кандидат | После изменения: первый кандидат |
| --- | ---: | ---: |
| Каждая линия разбита на два штриха, порядок изменён | 4/24 | 24/24 |
| Порядок штрихов и направление пера обращены | 24/24 | 24/24 |
| Наклон, изменение пропорций, плавная деформация, обратное направление пера | 23/24 | 24/24 |

Это небольшие синтетические проверки, использованные при разработке. Они не являются независимой оценкой точности на новых пользователях. Проверки также включают пустые/некорректные данные, каракули, недорисованную фигуру, перевёрнутые знаки, замену эталонов, загрузку после сетевой ошибки, сборку на холсте, очистку во время ожидания, несколько указателей и активацию полного заклинания. Отдельный T-образный знак построен геометрически, без копирования записанного образца.

Проверка страницы в Safari: загрузка сайта, гримуара и подложки. Рисование пальцем и стилусом на физических устройствах не проверено.

## Что ограничивает результат

В гримуаре 67 символов, но в `client/public/reference-templates.json` есть записи для 24: 3 сигилов и 21 знака. Остальные 43 теперь помечены «нет образцов». Изменение алгоритма не создаёт отсутствующие данные и не делает доступными рецепты с такими символами.

Сохранены исходные образцы; новые зависимости и сервер распознавания не добавлены. Сравнение работает локально в браузере. Для независимой оценки нужны рисунки разных людей без обводки: хранить часть отдельно от эталонов и оценивать также ошибки/отказы, а не только первое место правильного кандидата. Существующий инструмент `tools/record-templates.mjs` позволяет пополнять базу, но автоматическое обучение по пользовательским исправлениям не добавлялось.

После копирования проекта установленные зависимости оказались повреждены. Для восстановления использовано `npm ci --ignore-scripts --legacy-peer-deps`: legacy-флаг нужен из-за имеющегося конфликта старого служебного Vite-плагина с Vite 7. Версии в lock-файле не обновлялись.
